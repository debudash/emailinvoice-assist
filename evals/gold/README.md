# Gold labels for the four sample invoices

One JSON file per sample email in `samples/emails/` (`simple`, `medium`, `large`, `mismatched-metadata`): the correct Context, the correct Line Match for every Line Item, and the expected Decision and Hold Reasons. These are the hand-labelled seed of the eval set (see docs/decisions.md, "Gold set").

**How they were made:** an AI agent derived them from `scripts/generate_sample_invoices.py` (the exact printed lines and the comments describing the planted anomalies) and the seed data in `services/api/seed/data/`. It checked each item code against the invoice's own sponsor+study Catalog and compared unit prices exactly. **They were reviewed on 2026-10-20** with the review page, now **Hub > Gold review** (reviewer DD, standing in for the subject matter expert who owns them in production) and every line and outcome was agreed, including the judgement calls; the feedback is in `review/`. The `notes` field in each file records the judgement calls.

**Fields:** `context`: true sponsor/study/site ids. `context_should_be_confident`: false only when the header should cause a Hold for uncertain Context. `lines[]`: `line_no` is 1-based in printed order. `description`, `qty` and `billed_unit_price` are as printed. `expected_item_code` is the best Catalog Item, or `null` for Unmatched. `acceptable_item_codes` lists every defensible code (`[null]` for Unmatched lines). `ambiguous` is true when more than one Catalog Item is plausible. `price_variance` is true when the unit price differs from the `expected_item_code` item's `unit_price`. `expected_decision` is `submit` or `hold`. `expected_hold_reasons` uses these values: `context_uncertain`, `site_not_linked`, `unmatched`, `ambiguous`, `price_variance`, `arithmetic`, `llm_concern`. Optional `review_note` (on a line) and `outcome_note` explain a judgement call in plain words for the subject matter expert; `reviewed_by` is set when Gold review changes an answer. All are written by `evals/make_gold.py` except `reviewed_by`; the eval ignores them. Once the subject matter expert has changed an answer, the gold files are the source of truth: rerunning `make_gold.py` would overwrite their changes.

For mismatched-metadata, lines are labelled against the true context (VERITAS, Prairie Field), so they can grade the run after a Reviewer Correction. That run is expected to Submit.
