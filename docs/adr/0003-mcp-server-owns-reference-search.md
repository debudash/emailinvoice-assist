# An MCP server wraps the reference API and owns name search

The brief requires context resolution "via the MCP-wrapped reference API", but the starter's REST API only lists records and fetches them by ID: it has no search. We built our own MCP server (ref-mcp) as a separate service in front of the unchanged REST API. Its tools do the useful work: fuzzy search with scored candidates for sponsors, studies and sites, and a Catalog tool that always fetches every page. That last point matters because the API's default page size of 50 silently cuts the 100-item LUMIN Catalog in half. The alternative was a thin pass-through MCP that mirrors the endpoints one-to-one. We rejected it because the agent would then have to list everything and do the matching itself, and the wrapper would add nothing.
