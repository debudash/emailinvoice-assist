# Extract by sending the document natively to the LLM, checked against its own text

The invoice PDF (or image) goes directly to Claude as a document input with a structured-output schema. We do not extract its text locally first, because local text extraction loses table layout on messier invoices. As a guard against invented numbers, each extracted amount and the invoice number are checked against the PDF's text layer, and a number that can't be found is a Hold Reason. Images have no text layer, so an image invoice holds as "extraction unverifiable", a Hold Reason the Reviewer can Release; a scanned PDF with no text layer is treated the same way.
