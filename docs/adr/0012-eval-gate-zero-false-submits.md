# The eval gate requires zero False Submits

The quality gate is asymmetric. Any False Submit fails it outright, and the other metrics only have to stay above their floors: Decision accuracy, Hold Reason recall and Line Match accuracy at 90% or more, Context accuracy at 95% or more. An Over-Hold costs a Reviewer a few minutes; a False Submit sends a wrong invoice to the sponsor's backend with no one checking it. One overall accuracy score would treat those two errors as equal. Labels are compared exactly against a gold set. In P0 that set is the four hand-labelled samples. In P2 it grows into a synthetic set of scenario-built invoices whose labels are correct by construction, with reworded descriptions drawn from a curated table that doesn't change, so the same model never writes the test cases it is graded on.
